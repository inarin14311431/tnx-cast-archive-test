# アクト紹介 X投稿用画像(予告ポスター)仕様

アクト紹介の公開完了カードから生成する、X投稿用の予告ポスター画像の仕様。実装は `js/act-poster-layout.js`(純関数: モデルと配置)、
`js/act-poster-render.js`(canvasに描く側)、`js/act-poster-text.js`(ALT文・投稿文・入力の上限と記憶)、`js/showcase-poster-panel.js`(公開完了カードの中の画面)。
この文書は実装(#728 と、画面を足した変更)に合わせてある。仕様と実装が食い違うときは実装を正とし、この文書を直す。

## 目的
X に「これからこのアクトを遊びます」と投稿するときに添付する、映画の予告ポスター風の画像を、公開完了カードから生成する。X の投稿画面を開く方式では画像を自動添付できないため、画像は「保存」「コピー」(PC)・「共有」(スマホの Web Share API)で渡す。

## 出力
- 論理サイズ 1200×675(16:9)。2倍(2400×1350)で描き、PNG。5MBを超えるときは JPEG(quality 0.9)。クリップボードへのコピーは常に PNG。
- 描画はブラウザの canvas。サーバー側の処理は不要。
- 立ち絵(Supabase Storage の公開画像)は fetch + createImageBitmap(または crossOrigin="anonymous" の img)で読む。CORS は確認済み。

## 載せる項目
- 必須: アクト名、HO番号、ハンドアウトのスタイル(カブト等)、ハンドル、氏名、ルビ(ハンドル・氏名の両方)、立ち絵、RL、ライター。
- 任意: 副題(公開したアクト紹介の `heroSubTitle`。既定の「CAST SHOWCASE」や空は出さない)、日付(入力欄。空なら「近日開演」)、キャッチコピー(入力欄。初期値はアクトトレーラー本文の最後の空でない行)。
- 載せない: キャストのスタイル3つ(チップ)、ハンドアウト本文、ゲスト、ハッシュタグ(投稿文側)、「公式」「公認」の語(権利表記の「公式の画像・サービスではありません」のように**否定して使うのは可**。公式・公認だと名乗る書き方は不可)。
- 下端の1行に権利表記を置く。左に注記(定数 `POSTER_RIGHTS_NOTICE`、`js/act-poster-layout.js` の1か所)「本画像は非公式ファンツール「CAST ARCHIVE」で生成したものです。各権利者による公式の画像・サービスではありません。」、右に著作権表記(右寄せ。`js/legal-rights-text.js` の `RIGHTS_TEXT`。サイトの法的表記 `js/legal-notices.js` と同じ文字列を1か所から共有)。文言は作者が現行のもので確定した(2026-11-10)。
- ロゴ・公式フォント・公式イラストは使わない。

## データの出どころ
公開済みアクト紹介のペイロード(js/act-showcase-page.js の createShowcaseModel が読むものと同じ。公開した直後は、公開した `showcaseData` そのもの)から作る。
- アクト名・副題・RL・ライター・トレーラー本文は、公開ページと同じ読み方(アクト名は `actName`、なければ `heroTitle`、`pageTitle`。RL は `rulerName`、ライターは `scenarioWriterName`)。
- reading は「“ハンドルの読み” 氏名の読み」の1本の文字列(例: “ニューゲーム” ヒュウガ ルカ)。js/act-showcase-handout-fields.js の splitCastName と同じ規則で、ハンドル側と氏名側に分ける。氏名の読みに空白があってもよい。引用符のない読みは氏名側の読みとして扱う。ハンドルのないキャストの読みは、氏名側だけ。
- fullName も同様に、先頭の引用符つきがハンドル、残りが氏名。
- ハンドルの引用符(“ ”)は表示に残す。ルビ側の引用符は外す。
- HO番号は、キャストの枠(`slot`、「CAST 01」)の数字。数字がなければ並び順。スタイルは、ハンドアウトの役割のスタイル(◎ ●は外す)。
- 画像は `http(s)` と `data:image` だけ読む。画像なし(URLが空、または公開時に入る `./assets/placeholders/scan-failed.webp`)・読み込み失敗は assets/placeholders/scan-failed.webp を使う。
  「SCAN FAILED」の文字が札に重ならないよう、1〜4人の構図では画像を上へ約85px(表示領域の約22%)ずらす。名簿型(5〜6人)ではずらさない。細い枠でも文字が欠けないよう、プレースホルダーは枠の幅いっぱいに出す。
- 画像は、透過があってもなくても、先にHO色のグラデーション背景を敷いてから描く。

## 人数ごとの構図
- 1〜4人: 立ち絵を斜め(−7°)の平行四辺形にして横に並べ、隣と少し重ね、上下をジグザグにずらす(1・3人目が下、2・4人目が上)。全員同じ大きさ。名前の札は各立ち絵の下端に重ねる(札は立ち絵の下へ少しはみ出る)。
- 5〜6人: 3列×2段の名簿型(カード 360×205、列の間隔20、段の間隔14)。各カードは左に立ち絵(108px幅)、右に HO番号+スタイル、その下にハンドル・氏名(1行。全員の最小の文字サイズにそろえる。12〜22px)。札は無い。
- 1人・2人は同じ作りで幅を広げる(立ち絵の幅は400px)。

## 名前の札
1. 全員を1行(ハンドル+氏名を横に並べ、それぞれの上にルビ)で、札の幅に収まる最大の文字サイズを求める(最大36px)。全員の最小値で文字サイズを揃える。
2. 揃えた文字サイズが26px以上なら、全員1行。
3. 26px未満なら、全員を2段(上段=ハンドル、下段=氏名。各段の上にルビ)にし、文字サイズを28pxにする。札の高さは全員で揃える(ルビがない行もルビの行の高さを空ける)。札は60px上げる(上端が立ち絵のy+336から y+276へ)。
   2段の行が札の幅より広いときだけ、その行を16pxまで縮める。
- 1行と2段が混ざることはない。ハンドルのないキャストは、氏名だけ(1行では引用符なし、2段では上段に氏名)。

## ルビ(均等割り付け)
キャスト閲覧画面・SNS紹介(js/cast-sns-name-layout.js)と同じ見え方にする。
- 字間 0.2em。サイズは既存の READING_SCALE に合わせる。
- 基準は、ハンドルでは引用符を含めた “ハンドル” 全体、氏名では氏名。
- 読みの幅が基準の文字の幅より短いとき: 読みの文字を、基準の幅いっぱいに均等に置く(CSS の ruby-align: space-around と同じ。両端に半分の余白)。
- 読みの幅が基準より長いとき: 基準の文字の左右に余白を足して読みの幅に合わせる(基準が中央に寄る)。
- 計算は DOM に依存しない関数(`computeRubyUnit`、`computeNameLayout({ readingMode: "space-around" })`)で、js/cast-sns-name-layout.js にある。既定の `center` はSNSカードのまま。

## 配色・書体
- テーマ(primary / secondary / accent)から取るのは、HOごとの色、タイトルのずれ影とグロー、RL・ライターのラベルの色だけ。HOごとの色はキャスト順に primary / secondary / accent を繰り返し、4人目以降は導出した補助色(明るく、次は暗く)。
  3色は、公開したアクト紹介のテーマ(`showcaseData.theme`: nova / intron / vlad / lutetia)のパレット(生成画面のテーマカードと同じ `getThemeSwatchColors` の2〜4番目)で、canvas に渡す前に getComputedStyle で解決する(`resolvePosterTheme`)。
  生成画面には、公開ページの `--showcase-*` 変数が無いため、変数を読むのではなくパレットを渡す。暗い地で見えない色(明るいテーマの黒)は、見えるまで白へ混ぜる(`readableOnDark`)。
- それ以外(暗い地、グリッド、光の筋、走査線、金のキャッチと日付、白→水色のタイトル)は固定デザインで、テーマに従わない(`js/act-poster-render.js` は `audit:colors` の対象外。`docs/UI_CONVENTIONS.md`)。配置を決める `js/act-poster-layout.js` は色を持たない。
- タイトル(アクト名): Dela Gothic One。白→水色の縦グラデーション、secondary のずれ影(右下3px)、primary の弱いグロー。
- 本文: Noto Sans JP(700/900)。HO番号・日付の数字: Orbitron。
- 書体は、これを使う画面(`showcase-generator.html`)が `<link>` で読み込む(Dela Gothic One、Noto Sans JP 700/900、Orbitron 700/900 だけ)。canvas で描く前と配置を測る前に document.fonts.load で必要な書体を読み込み終えるのを待つ。

## レイアウト(論理座標 1200×675、1〜4人)
- 背景: 暗い地(#04070f系)+ 40pxのグリッド線(薄い)+ 斜めの光の筋(−8°、高さ90px)+ 走査線(4pxごとに1px、薄い)。
- 立ち絵: 3人は幅372・刻み346、4人は幅300・刻み278、左x=40、高さ392、y=44/8/44/8(3人は44/8/44)。平行四辺形(−7°)、外周にHO色の2px線と影。画像は上寄せ(object-position 50% 6%)で cover。上にHO色の薄い重ね、下側に暗いグラデーション。
- 札: 立ち絵の下端付近(1行版は y+336、2段版は y+276)に、立ち絵と同じ傾きで重ねる。暗い半透明の地、左に5pxのHO色の線。1行目に「HO番号(HO色の塗り)+ スタイル名(HO色の文字)」。
- 下段(左から順に、キャッチ → タイトル → 副題 → RL・ライター): キャッチ(金、letter-spacing .34em、16px)、タイトル(アクト名、56〜68px、日付に重ならないよう自動縮小。それでも収まらなければ24pxまで縮める)、副題(19px、水色)、RL・ライター(20〜24px、ラベルは色つき平行四辺形。RLは primary、ライターは secondary)。
  右に日付(金。最初の空白まで=「11.23」を数字80〜96px、残り=「SUN 21:00〜」を26px)。
- 最下行: 左に注記、右に著作権表記(右寄せ、x=1160)。ともに11px・同じ基線。注記は、2つが収まらないときだけ縮める(下限9px、間は24px以上)。
- 日付が空のときは「近日開演」を同じ位置(大きい方の欄)に出す。

## 画面(公開完了カード)
公開完了カードの「X に投稿」の下に「投稿用画像を作る(POSTER IMAGE)」を置く。開くと(`aria-expanded`)、日付・キャッチの入力、プレビュー(canvas を縮小して表示)、「画像を保存」「画像をコピー」「共有」、ALT文が出る。
パネルは、初めて開いたときに読み込む(生成画面は、ポスターのモジュールを最初から読まない)。日付・キャッチが変わると、250msのデバウンスのあとで描き直す。生成中・生成できなかったときは、プレビューの下に出し、保存とコピーは使えなくする。

## 入力(公開完了カード)
- 日付: 自由入力1欄(例: 11.23 SUN 21:00〜)。最大24文字(入力欄の maxlength と、モデルの切り詰めの両方)。
- キャッチ: 自由入力1欄。最大40文字(同上)。初期値はアクトトレーラー本文の最後の空でない行。トレーラーがなければ空(キャッチ行を出さない)。空にして消したときは、初期値に戻さない。
- 入力値は DB に保存しない。同じタブ内で sessionStorage にアクト(識別名)ごとに覚えるだけ(try/catchで包む。使えなくても動く)。
- 入力が変わったら、少し待ってから(デバウンス)プレビューを描き直す。生成中・失敗は、プレビューの下に出す。

## 共有
- PC: 「画像を保存」(download。ファイル名に識別名を含める: `act-poster-<識別名>.png`)、「画像をコピー」(ClipboardItem、PNG)。コピーに対応しないブラウザでは、ボタンを無効にして、保存を案内する。
- スマホ: navigator.canShare({ files }) が真のときだけ「共有」を出す(navigator.share({ files, text, url }))。
- ALT文(アクト名、副題、RL、ライター、HOごとのスタイル・ハンドル・氏名・読み。Xの上限1000文字以内)を、コピーできる形でプレビューの下に出す。
- 投稿文(「X に投稿」)は、アクト名(あれば副題)・RL・ライター・HO一覧・#トーキョーNOVA・公開URLから作る。データがなければ、アクト名とハッシュタグだけの従来の文面。文字数の調整はしない(Xの画面で本人が直す)。

## 守ること
- 既存データを変更しない。DB・migration・RLS・Storage設定は触らない。画像は読むだけ。
- ハンドアウト本文・ゲストは画像に出さない。
- 画面の文言・見た目は docs/UI_CONVENTIONS.md に従う。

## 実装(#728)との対応: 最初の仕様からの変更点
最初の仕様(会話で承認)と実装が食い違った点は、実装を正として上の本文を直した。
- 「SCAN FAILED」のずらし: 最初は「どの構図でも約85px上へ」。実装は、1〜4人の構図だけ約85px(392pxの約22%)上へ。名簿型では札がないのでずらさず、枠の幅いっぱいに出して文字が欠けないようにした。
- 色: 最初は「色を直書きしない」。実装は、テーマに従うのはHOごとの色・タイトルの影とグロー・ラベルの色だけで、暗い地・金・白→水色は固定デザイン(`audit:colors` の対象外)。配置の純関数は色を持たない。
- タイトルと副題: 最初は「アクト名の副題(水色)」。実装は、タイトルがアクト名、水色の副題が公開した `heroSubTitle`(既定の「CAST SHOWCASE」は出さない)。
- 2段の札: 28px固定だった。札の幅より広い行だけ16pxまで縮める。
- ルビの基準: ハンドルでは引用符を含めた “ハンドル” 全体にそろえる。ハンドルのないキャストには、ハンドルの読みを出さない。
- 日付: 最初の空白で、大きい部分と小さい部分に分ける。タイトルは日付の左に収まるまで縮める。
- 画像なしの判定: 公開時にキャスト画像がないと `./assets/placeholders/scan-failed.webp` のパスが入るので、これも画像なしとして扱う(その画像を「立ち絵」として描かない)。
- 権利表記の定数は、描画側ではなく純関数側(`act-poster-layout.js` の `POSTER_RIGHTS_NOTICE`)の1か所(`buildPosterModel` の既定値のため)。著作権表記は `legal-rights-text.js` から取り込む(`copyrightNotice`)。
